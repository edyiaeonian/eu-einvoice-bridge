# 背景研究:歐盟電子發票法規與市場現況

本文件記錄專案啟動前的法規與市場調查。技術設計見 `docs/superpowers/specs/`。

---

## 1. 法規背景:ViDA

歐盟 ViDA(VAT in the Digital Age)於 **2025-03-11 正式通過**、**2025-04-14 生效**,規定 **2030-07-01 起**歐盟境內跨境交易(intra-Community)必須使用符合 **EN16931** 的結構化電子發票。

各成員國國內強制時程並不同步:

| 國家 | 時程 |
|---|---|
| 比利時 | 2026-01 |
| 波蘭 | 大企業 2026-02-01、全體 VAT 企業 2026-04-01、微型企業 2027-01-01 |
| 希臘 | 2026-03 |
| 法國 | 2026-09-01 全體須能接收、大中型須開立;中小微開立 2027-09 |
| 德國 | 2025-01-01 起全體須能接收;開立 2027-01-01(營業額 >€80 萬)、2028-01-01 全體 |
| 匈牙利 | NAV RTIR 自 2018-07-01 起,2021 年起全面涵蓋 B2B/B2C |

這種「歐盟訂語意標準、各國各自實作國家格式與時程」的結構,正是本專案要處理的技術問題。

---

## 2. 為何不將本專案商業化

本專案曾評估作為創業題目,結論為**時機與條件均不利**,因此定位為技術作品集。

**市場飽和度**
- 匈牙利自 2018 年即強制 RTIR,市場飽和逾七年,企業早已全數導入方案
- 波蘭主要強制浪潮於 2026-04 結束,已過去逾五個月,急迫性紅利大致用盡

**既有競爭者**
- 企業級:Sovos、EDICOM、Pagero、Storecove
- 波蘭在地 ERP:InsERT nexo、Comarch ERP Optima、enova365
- 全球型低價方案:Invoicemonk(約 $15/月)

**尚存的窗口與其障礙**
法國(2027-09 中小微開立)與德國(2028-01 全體)仍有時間窗口,但需要在地法遵關係與銷售通路,這是遠端獨立開發者最難取得的兩項資源。

**Peppol 的角色**
自行取得 Peppol Access Point 認證並不實際(需 OpenPeppol 會員資格與 ISO 27001)。實務做法是接用現成 AP 供應商(約 €0.18–0.25/張,部分供應商有免費方案)。本專案不涉及 Peppol。

## 3. 沙箱可及性調查

此項調查直接決定了專案的技術路線。

**波蘭 KSeF ✅ 可用**
- 測試環境 `api-test.ksef.mf.gov.pl`,規定使用匿名資料
- 接受標準測試用假 NIP(如 `5555555555`)
- 測試環境可在無真實授權下取得 token,自簽憑證自動產生
- **不需要波蘭法人或稅號**

**匈牙利 NAV ❌ 不可用**
- 註冊需 Ügyfélkapu+(匈牙利政府電子閘道帳號)與匈牙利稅號
- 測試環境僅供已登記的納稅義務人使用
- **無匈牙利法人實體即無法取得存取權**
